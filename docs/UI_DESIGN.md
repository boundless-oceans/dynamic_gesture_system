## 一、首页

> 【已更新 2026-10】**不再是"一排按钮 + 左右箭头"**。现在是**两排卡片**，
> 所有尺寸都由窗口尺寸算出（响应式），没有写死的像素值。

- 大标题"庐州非遗"：居中，字号随窗口宽度缩放
- 左上角：印章「非遗珍宝」（尺寸随窗口缩放）

- **第一排：非遗项目卡**（每张 = 缩略图 + 项目名）
- **第二排：非遗传承人卡**（目前无照片，是**纯文字卡**：姓名 + 所属项目）

  - 卡片尺寸 = 可用宽/高按张数与宽高比算出；**选中卡放大 1.08 倍**，
    而"放大后"的宽度**已经算进整排的总宽预算**，所以选中哪张都不会把整排顶得位移
  - 选中卡：橙色粗边框 + 一道扫过的光条；"变大"是 200ms 的缓动
- **卡片区上边界要让开右上角的摄像头悬浮窗**（`HOME_TOP_RESERVE_PX`），
  下边界让开底部两个全局按钮
- 下方：关闭摄像头 / 手势说明两个按钮，始终存在
- 背景：白色到蓝色渐变 + 水墨粒子（粒子数与刷新率会**跟着空闲程度降频**）

## 三、通用

- 摄像头开启时画面始终在右上角
- 关闭摄像头按钮始终在页面下方
- 背景色：白色到蓝色渐变 + 水墨粒子（所有页面共用，见 `src/ui/base_page.py`）
- **换页有交叉淡入淡出**（`src/ui/page_fade.py`）：取上一页的快照盖上去再淡出
- **"已执行"提示在屏幕下方居中**（`src/ui/toast.py`）：淡入 + 上浮，
  约 1 秒后淡出。⚠️ 刻意不放右上角 —— 访客做完手势时视线在屏幕正中，
  放角落大概率看不见

### ⚠️ 动效上的两条硬约束

- **别用 `QGraphicsBlurEffect`**：每帧全屏重算，在纯 CPU 展台上很贵。
  `QGraphicsDropShadowEffect` 也只挂在静态控件上（标题），别扩大到每帧变化的东西
- **所有周期性重绘都要随可见性启停**（`showEvent` / `hideEvent`）——
  展台 24 小时开着，藏起来的页面不该还在烧 CPU

### ⚠️ 画在父控件上的东西会被子控件盖住

卡片右上角那个点赞角标（`♥ N`）**踩过一次**：一开始是画在卡片的 `paintEvent` 里的，
而卡片上还有缩略图和标题这两个 `QLabel`。Qt 是**画完父控件才画子控件** ——
于是角标被它们盖掉了**大半**，而且是被半透明的图片底纹冲淡的那种盖：字段全对、
坐标全对、`grab()` 出来也确实变了几个像素（实测只有 136 个），**看着就像"没画"**。

改成 `_LikeBadge(QWidget)` 子控件之后，可见像素从 136 涨到 **826**。

两条配套约束：

- 它必须 `WA_TransparentForMouseEvents` —— 否则它会**吃掉点击**，
  正好点在那儿的用户"点不动卡片"，而且没有任何提示
- 位置不能自己盯 `resizeEvent`，由 `_ItemCard._apply_size()` 统一叫它一声
  —— 卡片尺寸变（窗口拉伸、选中放大）就得重算，两处各算一遍必然对不上

**教训**：要在有子控件的控件上"叠一层东西"，先问一句**它会不会被盖住**；
靠"字段里存了值"是验不出来的，得比像素。

### ⚠️ 样式表会一路传给子控件 —— 包括弹窗

设置页那个「清空点赞计数」的确认框**黑过一次**，表现是操作员点不动按钮、
于是"点了没反应"。查下来是**样式表继承**：

主窗口在页面容器上设过 `background: transparent`（见 `main_window` 里 `central`），
而 **Qt 的样式表是往下传的** —— `QMessageBox` 是设置页的子窗口，底色跟着变成透明，
在 Windows 上直接渲染成**一片纯黑**（实测平均亮度 **229 → 3.8**）。

**任何自建的 `QDialog` / `QMessageBox` 都必须显式给底色**，不能指望默认样式。
（`main.py` 里那两个启动告警用的是 `QMessageBox.warning(None, ...)` —— parent 传 None，
不在那棵样式树里，所以一直正常，问题只出在**有 parent 的**那些。）

**教训**：在这套 UI 里弹任何东西，先用 `grab()` 看一眼像素 ——
"代码写得好好的"和"屏幕上能看见"是两回事。
